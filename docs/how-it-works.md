# Как это устроено

Сайт лежит на GitHub Pages. Публичного слоя данных у него нет: всё, что он
показывает, — дела, зашифрованные паролем и лежащие в том же репозитории.

Репозиторий публичный, и это осознанно: скрывать нечего, кроме содержимого дел,
а его прячет шифрование, а не закрытость репозитория.

## Кто что делает

```
tools/vault.py  ──пишет──>  my-data.json + index.json  ──читает──>  index.html
   (с машины)                  (в репозитории)                        (в браузере)
```

**Сайт только читает.** Pages отдаёт статику: писать в репозиторий из браузера
нельзя. Поэтому в интерфейсе нет ни формы дела, ни кнопки «добавить», ни даже
галочки «сделано» — всё это, заведённое в браузере, осталось бы в этом браузере
и на телефоне не появилось бы.

**Файлы правит утилита** `tools/vault.py`, запускаемая с машины. Результат
уезжает обычным коммитом, Pages пересобирается за минуту, и на всех устройствах
сразу свежее расписание.

## Формат файлов

```json
my-data.json   {"v": 1, "items": ["<base64>", "<base64>", ...]}
index.json     {"v": 1, "salt": "<base64, 16 байт>", "index": "<base64>"}
```

Каждый элемент `items` — **отдельное дело со своим вектором инициализации**.
Отсюда два свойства, ради которых так и сделано:

- новое дело дописывается **одной строкой**, прежние остаются байт в байт теми
  же — файл читается в diff'е и не переписывается целиком;
- дело правится точечно, не задевая соседние.

Фрагмент внутри:

```
base64( iv[12] ‖ AES-GCM(key, блок)[512+16] )

блок = size[2] ‖ json ‖ нули до 512 байт
```

Два байта настоящей длины впереди, дальше json дела, дальше набивка нулями.
`size == 0` — пустышка, при чтении она даёт `null` и пропускается. Отсюда предел
в 510 байт на дело: кириллица весит по два байта, и длинная заметка не влезает —
утилита скажет об этом и не запишет.

Индекс шифруется одним куском, без набивки: он не дело, и его длина ничего о
содержимом не говорит. Внутри — пары «дата — позиция фрагмента»:

```json
[{"d": "03.09.2026", "p": "19:45", "h": "repeat", "i": 12}, ...]
```

`h` — горизонт или `repeat`: по нему сайт понимает, какие фрагменты нужны
показанному отрезку, а какие действуют всегда (правила, вопросы, повторы).

## Ключ

Из пароля выводится PBKDF2-HMAC-SHA256, 150000 итераций, соль — 16 байт из
`index.json`. Результат — 32-байтный ключ AES-GCM.

**Соль лежит в файле, а не в браузере.** Иначе на втором устройстве из того же
пароля вывелся бы другой ключ. Порядок: пароль → скачали индекс → взяли соль →
вывели ключ → расшифровали нужные фрагменты.

Пароль служит двум вещам сразу: пускает внутрь (в `index.html` лежит его
SHA-256) и даёт ключ к файлам. Ключ живёт в `localStorage` — пароль вводится
один раз на устройстве и держится, пока не почистить данные сайта. Кладётся
именно ключ, а не пароль: сам пароль после входа нигде не остаётся.

**Смена пароля — это перевыпуск файлов**, а не только новый хэш:

1. посчитать SHA-256 нового пароля, вписать в `PASSWORD_HASH`;
2. обновить `.env`, удалить `index.json` и `my-data.json`;
3. `python tools/vault.py import --file seed.json --replace`.

## Что видно постороннему, а что нет

Открыто и так задумано: алгоритм, число итераций, соль, хэш пароля. Стойкость
держится только на пароле — прятать параметры схемы бессмысленно, сайт обязан их
знать, а его код видит каждый.

Скрыто содержимое дел: названия, время, заметки, метки, даты. Формы файла тоже
пришлось закрыть, иначе она выдавала бы то, что шифротекст уже спрятал:

- **все фрагменты одной длины** — иначе по размеру видно, насколько подробное дело;
- **число фрагментов кратно 16, остаток добит пустышками** — иначе видно, сколько
  всего дел и когда их стало больше.

Чего схема не обещает: файлы может скачать кто угодно и подбирать пароль у себя
сколько угодно. Стойкость упирается в пароль и в 150000 итераций, не больше.

Потеря пароля — потеря дел, расшифровать их нельзя по построению. Но не потеря
распорядка: он записан в заметке памяти, и залить его заново — одна команда
`import`.

## Работа с файлами

Пароль берётся, в порядке приоритета: `--password`, переменная окружения
`SCHEDULE_PASSWORD`, файл `.env` рядом с репозиторием, запрос в консоли.

```bash
python tools/vault.py list
python tools/vault.py list --from 03.09.2026 --to 04.09.2026 --filter-tag правила
python tools/vault.py add --subject "Подоить коз" --date 03.09.2026 --time 19:45 \
    --type Дойка --duration 30 --repeat пн,вт,ср,чт,пт,сб,вс --until 08.09.2026
python tools/vault.py edit --id 5019e955 --time 20:00
python tools/vault.py done --date 03.09.2026
python tools/vault.py rm --id 5019e955
python tools/vault.py import --file seed.json --replace
```

Ключ `--local` пишет в `my-data.local.json`: этот слой виден только при запуске с
localhost и в репозиторий не уезжает.

После правки — обычный коммит и push в `main`. Дальше минута-две, пока GitHub
пересобирает Pages.

Файлы данных запрашиваются мимо кэшей сразу: `cache: 'reload'` снимает кэш
браузера, метка `?v=<время>` — кэш Pages. Сама `index.html` кэшируется как
обычно: после коммита в код интерфейс может выглядеть старым, лечится Ctrl+F5.

## Локальный запуск

```bash
python -m http.server 8742
```

и открыть `http://localhost:8742`. Файлы берутся из корня репозитория, так же
как на Pages.
